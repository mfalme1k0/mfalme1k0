## How I think about engineering

> Where does this business rule belong?
> What happens when the network disappears?
> What happens when the input is wrong or hostile?
> Can this be tested on its own?
> If the requirements change, how much has to change with them?

I like to understand the problem before reaching for an implementation, and I write software that behaves predictably when things go wrong. Doing this job well means being calm in the middle of a rush and caring about the person using the result, which are things I learned long before I wrote any code.
